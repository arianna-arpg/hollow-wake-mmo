# Content layers and expressions

See `docs/modding.md` for the authoring guide. This is the contract.

## Loading

`ContentRegistry.Load(layers)` reads every YAML and JSON file in each layer directory in path order, merges entries by kind and id across layers (replace, patch, remove), binds each entry to its kind's record type through the content JSON conventions, expands attribute families into attributes, builds the attribute catalog and the rules, then runs every validator of every kind with a context that can resolve references to any other kind. A kind's own validator comes first; areas that add fields to a kind add their validators with `ContentKinds.AddValidator`. The report carries errors and warnings with origins. Strict loading throws on errors.

## Conventions

- Keys are snake_case; records map them by naming policy or explicit names.
- Tag sets accept arrays or space-separated strings; tags are lowercased; dots make hierarchies (`weapon.sword` satisfies `weapon`).
- Expressions accept numbers or formula strings; percent literals divide by one hundred.
- Typed specs are objects with a `type` key; the rest are parameters bound by the handler.
- Numbers read from JSON nodes go through `JsonNum` because YAML integers, YAML floats and wire JSON produce different node types.
- Unknown keys warn; missing required keys error; wrong types error with the entry's origin.
- The loader validates document `kind`, list-entry `id`, and optional `patch`/`remove` controls before applying an entry. Invalid metadata produces an error with the source file instead of a conversion exception; valid sibling entries and later files still load for diagnostics. A malformed control cannot replace or remove an existing definition. Strict loading rejects the completed report. Absent or null optional controls retain their false default.

## Expressions

Grammar: numbers (with optional `%`), identifiers with dots, strings in quotes (only as `has()` arguments), `+ - * / % ^`, comparisons, `&& || !`, `? :`, function calls. Division by zero yields zero. Unknown identifiers throw at evaluation; validation warns about identifiers that are neither attributes nor declared scope names.

Functions: `min max clamp floor ceil round trunc abs sign sqrt pow log exp lerp inverse_lerp step smoothstep pct avg sum diminish`, plus the forms the parser knows: `has("flag")`, `rand()` (a fraction from the scope's random stream), `randi(lo, hi)` (a whole number from lo to hi inclusive, from the same stream), `curve("name", t)` (a named curve at t; an unknown name fails parsing) and `if(c, a, b)`. Registration adds more functions.

Scopes: `DictScope` for tools and tests, `ScopeOverlay` for layering values and mounting sub-scopes under prefixes, `Stats` for entities, `WeaveScope` for `weave.*`, the effect context which mounts `source`, `target`, `caster`, `weave` and its variables, and the hit scope of a hit's folds where `target.*`, `source.*` and `distance` resolve.

Curves: `Curves` names shaping curves (`linear`, `quadratic`, `quad_out`, `exponential`, `breath` ...) that ramps and envelopes refer to by name; registration adds more.

Read-only observers can inspect `Expr.IsPreviewSafe` without evaluating the tree. Random forms are unsafe; all branches and arguments participate. Built-in numeric functions and curves are pure. Custom `ExprFunctions.Register` and `Curves.Register` calls default to unsafe for previews, while remaining executable. `previewSafe: true` explicitly promises a deterministic function of arguments only, with no external reads, writes or random draws. Registration happens before content runs. Parsed function calls retain their registered implementation and purity promise; curves resolve by name at evaluation, so their safety is checked against the current registration. Scope identifiers and flags still need separate dependency analysis: a tree with no random calls can refer to a random attribute formula. The shared [delivery forecasting](cast-forecasting.md#implemented-core-foundation) preflight performs that analysis before using the ordinary numeric fold.

## Composition lint

`hollowwake lint` (`CompositionLint`) names what breaks the combat grammar, in which every mechanic is a value on an axis or a node in a graph rather than a bespoke piece; it reports and never fails validation, and each finding is a `smell` (the grammar says it should change) or a `note` (worth a look). `form.one_use` and `form.unused` count the presets composing on each form: a shell (`drop_weight: 0`) exists to serve every preset of its kind, so one preset or none is a smell, while for a form that codices teach, which players compose on too, it is a note. `parameter.single_use` names an effect parameter exactly one definition writes, and `parameter.unused` one a handler's signature declares that no loaded content writes (or a whole effect type nothing uses); the lint finds effect nodes at every depth of every kind the way the weave compiler does, and counts what a patch's `set` and its wrapper write. `axis.frozen` names a literal number, or an expression that reads nothing, written in a form, preset or glyph graph for a parameter whose handler would otherwise read a weave attribute (`radius` on `area` reads `area.radius`, `count` on `projectile` reads `projectile.count`, `count` on `summon` reads `summon.count`), so no glyph, passive or item moving that attribute reaches it; the table of those fallbacks is read from the handlers and kept in the lint, and a multiplier such as `area.angle` is not one, since it still scales a literal angle. `expression.copied` names a formula, the same text but for whitespace, written in the graphs of five or more definitions (`--copies` sets the number), which a named basis in `rules.yaml` or an attribute should carry instead. `code.string_switch` reads the C# under a source root (`src/HollowWake.Core` by default, `--code` for another, `--no-code` to skip) a line at a time with comments and string contents masked, not as a compiler: every switch over string words is reported, a smell inside `Systems/`, `Effects/Handlers/`, `Combat/`, `Ai/`, `StatusEffects/` and `Weaves/` or wherever it re-lists effect types, a note elsewhere and where a handler parses its own choice words at compile time; inside those directories a line is also a smell when it tests a flag, tag or mechanism by a literal name, compares with a literal naming content (a status, tag, flag, mechanism, resource, thread, charge, proc or attribute), or compares one operand with two or more literals in the file, a switch written as ifs. It sees literal words only: a name behind a constant, a type check by component, a switch whose cases are constants and comparisons in other directories (`Sim/`, `Movement/`, `Minions/`) are invisible to it, and a line that registers words (`Register(`) is never a finding. `code.form_read` reads the same masked lines of `Weaves/`, `Systems/` and `Combat/` for members read through a `Form` (`weave.Form.Channel`, a compiled weave's own `Form.Targeting`, a mechanism probe's `w.Form.Toggle`): the runtime should read the compiled weave, into which a preset or glyph can merge any block, so these reads are the baseline later work shrinks. It matches the member access only, so it cannot tell a weave's form from another object's `Form`, and it does not see a form copied whole into a local (`var form = weave.Form`) or handed to a helper (`IsInstant(face.Form)`), the reads made through those, or form reads in other directories. `--json file` writes the report grouped by check.
