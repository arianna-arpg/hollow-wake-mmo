The owner asked the integration chat, forecasting chat and Claude to implement shared forecasting in both clients, with content composition instead of per-skill branches. Work is isolated in `codex/shared-cast-forecasts-integration`, initially based on main `dcecf647`, then combined with `91f234f`, `9e3deee` and approved appearance/port main `32f194b` in `013a052`. Integration fixes `db752e0` and `eb842ad` connect body motion to confirmed lifecycle and isolate browser card baking from the world viewport. Earlier commits are preserved without rewriting history. The integration checkout is untouched.

## Change and ownership

The implementation composes #6's confirmed cast/outcome stream, #11's shared delivery plan, and the forecasting chat's [positional-hit/runtime work](2026-10-17-cast-forecast-core.md). Every active cast has authoritative timing. Supported area roots expose the same resolved candidate shape used by execution, after forms, Threads, glyphs and live modifiers. The shipped melee attacks now use authored sectors and common release checks, so moving outside a committed swing can avoid damage. Armor, blocking and other build-based defenses still apply to landed hits.

The server sends opt-in `cast_forecast_v1` membership frames after interest refresh, with epochs, exact revisions, expiry, bounded membership and periodic full-record repair. Shared observation is cached per tick across viewers. Unchanged geometry is referenced rather than serialized repeatedly; a client missing the exact referenced revision removes that geometry until repaired. No future random outcome, hidden target position, or local timer is treated as a release.

Godot and browser consume `ui_cast_forecasts` for shape precision, colors, broken boundaries, direction markers, height-limit markers, screen-space timing panels and labels. Neither renderer switches on a spell, support, calling or monster identity. All registered shapes have combat-derived conformance fixtures, including narrow hollow variants. The fixture gate also checks current combat predicates and complete registered vocabularies.

The forecasting chat supplied core runtime/provider changes, melee content, core regressions and combat/delivery contracts. This chat owns transport, server routing, both clients, cross-client fixtures and integration evidence. Ownership notices were posted on #9, #11, #13 and [Claude's preset compiler #15](https://github.com/arianna-arpg/hollow-wake-mmo/pull/15#issuecomment-6243398804). #9's appearance work is now merged. The two integration corrections below are confined to the common lifecycle and renderer-state seams; the renderer defect and ownership were [posted on #20](https://github.com/arianna-arpg/hollow-wake-mmo/pull/20#issuecomment-6244514814). The combined base preserves cast cues, appearance, Crossing and quick play. No merge into main is included.

## Gameplay changes requiring review

Claude's [review](https://github.com/arianna-arpg/hollow-wake-mmo/pull/20#issuecomment-6243927697) correctly identified an unintended extra proc depth from wrapping direct melee damage in an area selector. `a2dee0a` adds reusable `area.payload_depth: same|next`, default `next`; the three replacement selector forms explicitly author `same`. Target count and miss reporting never imply this policy. Direct and selector-wrapped blows now have the same echo depths 1/2/3 and cap refusal. Ordinary areas retain their depth cost; delays, repeats, casts and area echoes still advance. Regressions also exercise delayed work at the cap. No skill name controls this behavior.
