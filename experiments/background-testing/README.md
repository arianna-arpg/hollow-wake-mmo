# Background testing evidence

Contract and usage: [docs/design/testing.md](../../docs/design/testing.md). Captured on Windows using the branch based on main `91f234f`; local machine paths are replaced with placeholders. Outputs generated by the harness and focus probe live under ignored `artifacts/testing/`.

`evidence/combined-result.json`, `browser-smoke.txt` and `native-smoke.txt` record one invocation of `node scripts/test-background.mjs --suite all`: fresh server data and distinct accounts, browser 25/25, native 23/23, no cleanup errors. Native theme pixels are explicitly skipped under the headless display. Browser screenshots are retained locally in the reported run's `shots/`; the isometric screenshot was inspected. GPU rendering is not a claim of the native run.

`check-focus.ps1` launches the suite with hidden child windows and samples Windows foreground ownership. It does not send input or activate any window. `evidence/focus.json` records no foreground ownership by the test process tree over 1,924 samples. Sampling can miss brief transitions; this supports the headless/hidden-process design rather than proving every possible operating system interaction.

`evidence/concurrent-browser-a.json` and `concurrent-browser-b.json` record overlapping `node scripts/test-background.mjs --no-build` invocations. They have distinct run directories, ports and server identities. Each suite uses a fresh browser context and account.

An earlier diagnostic run identified live controller polling as the source of a cancelled loading screen: `navigator.getGamepads()` exposed the operator's connected controller and its confirm press called `WebSocket.close(1000, "Loading cancelled")`. Background browser runs now install `web/scripts/isolated-input.mjs` before application code. The lifecycle regression supplies a pressed controller and verifies that the isolated page sees no controllers or connection events. Ordinary keyboard and pointer event paths are unchanged.

Gate summaries are retained in `evidence/build.txt`, `tests.txt`, `validate.txt`, `load.txt`, `fight.txt`, `web-tests.txt`, `web-build.txt`, `native-build.txt` and `runner-tests.txt`. The loopback and generated protocol tests are included in the server test count. The runner regression suite is also wired into CI.
